# ML Model Benchmark

Compares 5 scikit-learn regressors and 7 classifiers using k-fold cross-validation, with feature scaling kept inside each fold so no validation data leaks into training.

The project started as a model-comparison harness I wrote in June 2024 while taking the *Machine Learning A-Z* course. Reviewing it later, I found three evaluation bugs that made its scores unreliable. The git history keeps the original file, the fixes, and the rewrite as separate commits, so each change can be read on its own.

## Results

5-fold cross-validation, mean ± standard deviation across folds. Generated by `python benchmark.py`.

### Regression: diabetes progression (442 patients, 10 features)

| Model | R² | RMSE |
| --- | ---: | ---: |
| Linear Regression | 0.489 ± 0.090 | 54.527 ± 2.094 |
| Random Forest | 0.418 ± 0.098 | 58.276 ± 3.653 |
| Polynomial Regression (degree 2) | 0.412 ± 0.132 | 58.271 ± 4.622 |
| SVR (RBF kernel) | 0.157 ± 0.020 | 70.563 ± 3.225 |
| Decision Tree | -0.144 ± 0.104 | 82.026 ± 3.098 |

### Classification: breast cancer diagnosis (569 samples, 30 features)

| Model | Accuracy | Macro F1 |
| --- | ---: | ---: |
| Logistic Regression | 0.979 ± 0.014 | 0.977 ± 0.015 |
| SVM (RBF kernel) | 0.977 ± 0.007 | 0.975 ± 0.008 |
| SVM (linear kernel) | 0.975 ± 0.010 | 0.974 ± 0.011 |
| K-Nearest Neighbors | 0.965 ± 0.021 | 0.962 ± 0.024 |
| Random Forest | 0.965 ± 0.017 | 0.962 ± 0.018 |
| Decision Tree | 0.938 ± 0.015 | 0.934 ± 0.016 |
| Naive Bayes | 0.930 ± 0.012 | 0.924 ± 0.014 |

### What the results show

- **The simplest model won on both datasets.** Linear and logistic regression beat the ensembles here, because both datasets are small and close to linearly separable. A more complex model is not automatically a better one.
- **A single decision tree overfits.** Its negative R² means it predicts diabetes progression worse than always guessing the average. The random forest averages many trees and recovers most of that loss.
- **The spread matters as much as the mean.** On the classification task the top three models are within one standard deviation of each other, so the data does not support calling one of them the winner.

## Bugs found in the original harness

| Bug | Effect | Fix |
| --- | --- | --- |
| Regressors were fitted on the full dataset | Any test-set score was measured on rows the model had already seen, so it overstated accuracy | Fit on the train split only |
| The "Logistic Regression" block called the KNN classifier | Logistic regression never ran; its results were KNN's results under the wrong label | Call the logistic classifier |
| Classifiers reported R² on class labels | R² is a regression metric and is not meaningful for class predictions | Removed; accuracy and the confusion matrix remain |

`tests/test_original_fixes.py` checks each fix. The three bug tests fail when run against the original 2024 file and pass on the fixed version.

## How it works

`benchmark.py` wraps every model in a pipeline whose first step is `StandardScaler`. `cross_validate` refits the whole pipeline on each training fold, so the scaler learns its mean and variance from training rows only. Scaling the full dataset once before splitting would leak information from the validation fold.

Folds are shuffled with a fixed seed so results are reproducible. Classification uses stratified folds, which keep the class balance the same in every fold.

## Run it

Tested with Python 3.14.

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows; on macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python benchmark.py            # print both result tables
python benchmark.py --folds 10 # use 10-fold cross-validation
python -m pytest               # run the tests
```

## Limitations

- Models use default hyperparameters. No tuning was done, so the ranking reflects the defaults, not each model's best performance.
- Both datasets are small, clean, and bundled with scikit-learn. Results on real business data with missing values and drift would differ.
- RMSE is in the diabetes dataset's own units of disease progression, so it is useful for comparing models here but has no meaning outside this dataset.
